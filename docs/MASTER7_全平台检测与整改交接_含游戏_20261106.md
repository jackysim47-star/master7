## 6. 三家充值流程专项处理单

每家公司分别验证前台选择 → 本地订单持久化 → 服务端建单 → 付款页面 → 可信通知或查单确认 → 商户/订单/金额/币种匹配 → 钱包只入账一次 → 后台流水 → 商户对账。

实施方需从当前部署的真实调用链找断点。逐项交回“所在文件/函数、对应接口、输入/输出、失败日志的脱敏引用、预期结果、实际结果、修订 SHA、复测证据”。资料未在本轮取得时标为待核实，不能归责厂家或认定用户未提供。

| 阶段 | 实施方检查重点 |
|---|---|
| Connected | 平台实际使用哪个商户、环境和服务器调用路径，配置检查与外部认证分开列证据 |
| Order | 重复点击、网络超时、未知结果和幂等建单；保留原唯一订单号 |
| Query | 成功/失败/待支付的精确格式与状态映射，查询频率和超时处理 |
| Callback | 验真、金额/商户匹配、重复/乱序、持久化后确认及重试 |
| Wallet | 可信付款确认与数据库唯一入账，后台和用户余额一致 |
| Reconcile | 平台订单/钱包流水、供应商流水与手续费/商户结算分别核对 |

当前仓库说明把 Wallet 勾选绑定到 `settlementVerified` 和 `liveReady`。实施方需解释这两个字段分别代表什么，并分别展示“会员钱包入账验收”和“商户结算验收”，避免状态灯让用户误解实际断点。
